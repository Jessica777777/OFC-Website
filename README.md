## 多語系切換（中文／英文／日文）

全站四個頁面都支援中文／英文／日文切換，右上角導覽列有一個三段式切換鈕（中｜EN｜日）。

**運作方式：**

- 每個可翻譯的文字節點都加了 `data-i18n="some.key"` 屬性；屬性值（如 `aria-label`、
  `alt`、`<meta content="...">`）則用 `data-i18n-aria-label` / `data-i18n-alt` /
  `data-i18n-content`。
- `js/i18n.js` 裡有三份字典：`I18N.zh`、`I18N.en`、`I18N.ja`，key 完全對應，切換語言時
  會抓對應字典把畫面上所有 `data-i18n*` 元素的內容替換掉。
- 使用者選擇的語言會存在瀏覽器的 `localStorage`（key: `ofc-lang`），下次造訪同一瀏覽器
  時會記得上次的選擇。
- 語言清單定義在 `js/i18n.js` 最上方的 `const LANGS = ['zh', 'en', 'ja']`；若要再新增
  語言，在 `LANGS` 加上代碼、在 `LANG_LABEL` 加上按鈕顯示文字、並在 `I18N` 物件裡新增
  對應的完整字典即可，導覽列的三段式切換鈕會自動多長出一個按鈕，不需要改 HTML。

**如何新增一個可翻譯的字串：** 在 HTML 裡幫該元素加上 `data-i18n="頁面.區塊.名稱"`
（key 命名風格可參考既有的 `index.hero.title`、`howToPlay.ofc.title` 等），然後在
`js/i18n.js` 的 `zh`、`en`、`ja` 三份字典裡各補一行對應的 key/value 即可。

首頁最上方（Hero 主視覺文字上方）預留了一個全寬「影片介紹」區塊（`index.html` 裡的

**之後有正式影片時，替換方式：**

- 若影片放在 YouTube：把 `.video-placeholder` 整個 `<div>` 換成
  `<iframe class="video-embed" src="https://www.youtube.com/embed/你的影片ID" ...></iframe>`

- 若要自行架設影片檔：改用 `<video class="video-embed" controls src="影片網址或路徑">`。
- 換成真的影片後，記得把播放鈕、`不可點擊` 的樣式與 `影片介紹即將推出` 文字一併移除。

## 內容調整紀錄（v26：B／C 區改版為滿版輪播——一次多格、自動播放＋可點擊跳轉、真正無縫循環）

你先請我針對「參考 ROG 筆電官網的功能特色輪播做法」寫優化提案（不要直接動工），提了三點：
（1）網頁改滿版、（2）B 區（Why us 功能卡片）比照 ROG 做法改成一次看多格、可點擊也可等待
自動輪播、圖片文字放大、且要能無縫循環（不能滑到底就卡住）、（3）C 區（Agent Collectibles
收藏輪播）比照 B 區升級，一次顯示更多格。我先寫了文字提案，你確認後回覆「B 區的圖到時候可以
重新裁切，先直接放大看看效果，開始做吧」，同意先用現有圖片放大測試效果，裁切留到之後再處理，
於是這次直接動工。

**改版前的狀態**：B 區是一個靜態的 4 欄 × 2 列 CSS Grid（v22 改版後的樣式），8 張卡片全部
同時顯示、完全沒有互動；C 區雖然已經是可以左右滑動的輪播（v13 起），但用的是瀏覽器原生
`overflow-x` + `scroll-snap`，只能用滑鼠拖曳或按箭頭手動切換，沒有自動播放，而且滑到最左或
最右就會卡住不動、無法繼續循環。另外整個網站的內容（含 B、C 兩區）都包在寬度上限 1160px 的
`.container` 裡置中顯示，在較寬的螢幕上兩側會有大量留白。

**這次做了什麼**：

1. **共用輪播引擎（新增，B／C 共用同一份程式碼）**：在 `css/style.css` 新增一組通用的
   `.carousel-wrap` / `.carousel-viewport` / `.carousel-track` / `.carousel-dots` /
   `.carousel-playpause` 樣式，並在 `js/main.js` 寫了一個 `initCarousel()` 函式，B、C
   兩區各自呼叫同一份邏輯（差異只在 CSS 變數 `--slides-visible`／自動播放秒數），避免同一套
   輪播行為要維護兩份程式碼。這個引擎提供：
   - **真正無縫循環**：實作方式是把全部卡片各複製一份分別接在最前面與最後面（例如 B 區
     8 張卡片，複製後軌道總共有 24 張），往後滑到超過最後一張真卡片時，會先讓瀏覽器把滑動
     動畫播完，動畫結束的瞬間再「無動畫地」把軌道位置瞬間換算回對應的真卡片位置——因為換過去
     的複製卡片內容跟真卡片一模一樣，這個瞬間跳動使用者完全看不出來，滑起來就像無限循環一樣，
     往前滑到第一張之前也是同樣做法。
   - **自動播放＋可點擊跳轉**：每區下方新增一排「進度點」，取代原本 C 區沒有、B 區也沒有的
     頁碼指示——目前作用中的那個進度點會有一條金色進度條隨秒數慢慢填滿，填滿後自動跳到下一張；
     使用者也可以直接點任一個進度點跳到指定張卡。滑鼠移到輪播上方、或用鍵盤 Tab 移入輪播範圍
     時會暫停自動播放，移開後才會繼續，避免使用者正在看某張卡時卡片突然被切走。
   - **播放／暫停按鈕**：進度點旁新增一顆圓形播放／暫停切換鈕（參考 ROG 頁面右下角的做法），
     使用者可以自行決定要不要自動輪播；這個「使用者主動暫停」的狀態跟前述「滑鼠移入暫停」是
     分開處理的兩件事——使用者按下暫停後，就算滑鼠移出輪播範圍也不會自動恢復播放，要再按一次
     才會繼續播放。
   - **拖曳滑動**：因為改成用 JS 控制卡片位置後，原本瀏覽器原生 `overflow-x` 附帶的觸控滑動
     手勢就沒有了，這次額外補上一段用滑鼠／觸控「按下→拖曳→放開」判斷方向的邏輯，桌面用滑鼠
     拖曳、手機用手指滑動都能觸發切換到上一張／下一張，體驗跟原本差不多，不會因為技術改動而
     倒退。
   - **無障礙與效能細節**：偵測到使用者系統設定「減少動態效果」（`prefers-reduced-motion`）
     時預設不會自動播放；輪播軌道本身可以用鍵盤方向鍵（←/→）切換；複製出來、純粹墊在頭尾做
     循環效果用的卡片都加了 `aria-hidden` 與 `inert`，螢幕報讀軟體與 Tab 鍵不會誤讀到重複的
     內容。

2. **B 區（Why us）改版**：`index.html` 把原本 `<div class="grid grid-4">` 包住的 8 張
   `.feature-card` 改成輪播軌道結構，套用共用引擎，`data-autoplay="5000"`（每 5 秒自動切換
   一張）。桌面版預設一次完整顯示 5 張卡片（`--slides-visible: 5`），依螢幕寬度往下依序降為
   4／3／2／1 張；卡片本身的圖片與文案排版沿用 v22 既有的 `.feature-card` 樣式沒有改動，但
   因為輪播貼齊瀏覽器邊緣（見下方第 4 點），加上文字區塊 padding、標題與內文字級都調大了一些，
   視覺上比原本塞在 1160px 容器裡的 4 欄小卡片明顯放大。**這次只放大版面尺寸、沒有重新裁切
   圖片本身**——8 張卡片用的仍是原本 900×675 的既有圖檔，是你這次明確說「先直接放大看看效果，
   B 區的圖到時候可以重新裁切」，等你確認這個新版面方向沒問題，之後再視需要重新輸出更高解析度
   的圖片。

3. **C 區（Agent Collectibles）改版**：原本的 `.collectible-carousel`（原生
   `overflow-x`／`scroll-snap`）換成跟 B 區同一份共用輪播引擎，`data-autoplay="4000"`
   （每 4 秒自動切換）。因為收藏品卡片本身比 B 區的大圖卡片單純（比較像徽章／獎牌的方形小

**C 區：直升機置中與縮小**

修法：重新以「靜止箱子畫面」的內容中心（而非整段動畫聯集中心）來抓裁切框，同時把裁切框

達不到「凸出框外」的效果，因為它離框的邊緣其實還很遠。

**處理方式**：

1. **重新裁切素材（`assets/collectibles/collectible-agent-reveal.webp`）**：直接從你上傳
   的原始 92 格高解析度 WebP 逐格計算透明像素的聯集範圍，重新裁切掉四周的空白畫布（新畫布
   約 636×459px，裁完後箱子底部幾乎貼齊畫布底邊、直升機最高點也幾乎貼齊畫布頂邊），這樣
   等一下要用 CSS 再放大時，才有意義——不然放大的是空白，不是動畫本身。裁切後維持跟 v19
   同樣的精簡策略（原始 92 格改成每 3 格取 1 格、共 31 格，寬度壓到 480px、品質 66），
   檔案約 680KB（比 v19 的 540KB 略大，因為裁緊後畫面裡「會動的東西」佔比變高，動態
   WebP 對變化大的內容壓縮效率本來就會下降，這是預期中的取捨）。
2. **用 CSS 從底部往上放大，讓頂部凸框（`css/style.css`）**：新增一組修飾類別
   `.collectible-slide-thumb--reveal`，把這一格的縮圖容器改成 `align-items: flex-end`
   （箱子貼齊方框底部，而不是像其他收藏品一樣整體置中），再對圖片套用
   `transform: scale(1.55); transform-origin: 50% 100%;`——以底部為錨點放大，箱子底部
   位置幾乎不動，直升機所在的頂部則跟著放大的比例被推出方框頂端，做出跟
   `.cta-agent-portrait img`（D 區特務圖頭髮出血）同樣的「刻意越界」效果。
3. **`.collectible-carousel` 的 padding-top 從 8px 加到 34px**：這個收藏品輪播因為要支援
   左右滑動，`overflow-x: auto` 會連帶讓瀏覽器把 `overflow-y` 也視為 `auto`（CSS 的既定
   行為，沒辦法只讓 x 方向捲動、y 方向完全不裁切），代表任何超出容器本身 padding 範圍的
   內容都會被裁掉看不見。放大後凸出方框頂端的直升機，如果容器本身的頂部留白不夠，一樣會
   被整個裁掉、等於白做——先算過在最大顯示寬度下直升機大概會凸出方框頂端約 18px，抓了
   34px 的安全空間（含滑鼠移上去卡片會有 4px 上浮效果的餘裕）。
4. **`z-index` 調整，避免動畫被輪播箭頭蓋住**：實際用 Playwright 逐格截圖檢查放大後的效果
   時，發現動畫過程中有幾格直升機會飛到畫面偏左側（這是動畫本身「直升機飛入」的過程，不是
   每一格都停在正中央），放大後那幾格會延伸到輪播左箭頭鈕的範圍，而箭頭鈕原本設定
   `z-index: 5` 高於縮圖，導致那幾格畫面會被箭頭鈕蓋住一角。已把
   `.collectible-slide-thumb--reveal` 的 `z-index` 提高到 6，蓋過箭頭鈕——實際效果是那幾格
   爆炸的煙塵短暫蓋住箭頭一角，因為時間很短、視覺上更像是有意的運鏡而不是排版錯誤，箭頭
   本身的點擊區域不受影響。

**已知取捨（沒有進一步處理，僅記錄）**：直升機在動畫過程中會左右飛動，不是每一幀都停在
正中央，所以「凸出框外」的視覺效果在動畫循環的不同時間點強弱不一——有些幀凸出得很明顯
（直升機清楚飛出頂端，效果最好），有些幀因為直升機還在框內飛行、凸出感較弱。這是素材本身
動態內容決定的，沒有針對特定幀做特殊處理。

**發佈與同步**：已用 Playwright 在動畫循環的多個時間點分別截圖確認效果（含直升機凸框最
明顯的幾幀），也確認過手機寬度（420px）下比例仍正常、沒有跑版。網站檔案已同步回你的
「Desktop/claude/OFC website」資料夾。

## 本地預覽
